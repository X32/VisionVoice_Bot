## 2. 架构与线程模型

```
mic_loop（主线程，唯一麦克风流）
  │ 512样本/块 (32ms)
  ├─ 回声门控：mute_until 内 → 丢弃（不进VAD也不进KWS）★原有机制，原样保留
  │
  ├─ IDLE（待唤醒）
  │    └─ 音频只喂 KeywordSpotter → 命中 → ACTIVE + on_wake回调
  │       （不进VAD/ASR/LLM——拦截在源头，IDLE下任何对话不消耗LLM）
  │
  └─ ACTIVE（对话中）
       ├─ 超时检查：now - last_voice_time > 30s → IDLE + on_sleep回调
       └─ 现有管线照旧：silero VAD断句 → SenseVoice ASR → text_q
                                                            │
worker线程（不变）: text_q → LLM(+工具) → TTS播报（mute→播→unmute tail）
```

关键设计决策：
- **单音频流分流**：KWS 与 VAD 共用同一条 `sd.InputStream`，按状态分流，不开第二个流抢 ALSA 设备
- **唤醒应答预合成**：启动时用 TTS 合成好"哎，我在"的样本，命中后直接 `sd.play`（现场合成需 ~0.5s）
- **唤醒应答也走回声门控**：`on_wake` 中 mute→播→unmute(tail)，防止应答音被自己识别成指令

## 3. 休眠时机详解（本报告重点答疑）

**问题：唤醒后问完问题，什么时候恢复待唤醒模式？**

**答案：从"最后一次检测到用户语音活动"起算 30 秒（`--active-timeout` 默认值），机器人回答的耗时不算在内。**

`last_voice_time` 的刷新点（`vad_asr.py` mic_loop 内）：

| # | 事件 | 位置 |
|---|------|------|
| ① | 唤醒词命中，进入 ACTIVE | 状态机 idle→active 分支 |
| ② | VAD 检测到语音开始（`is_speech_detected` 翻转） | VAD 段落检测处 |
| ③ | 断句段落弹出（你说完一句话，静音 0.5s 后） | `vad.pop()` 后 |

典型时间线（用户问完一个问题）：

```
t=0    你开始说话                    → 刷新②
t=3    你说完，0.5s静音后断句弹出     → 刷新③（最后一次刷新）
t=3~5  LLM思考                       → 不刷新、不检查超时
t=5~9  TTS播报回答                   → 回声门控丢弃音频块，
                                        超时检查被跳过（冻结）
t=9    播报结束 + 0.8s回声尾巴
t=39   此间你未再说话                 → 回 IDLE，打印"💤 超时无语音，
                                        回到待唤醒..."，需重新说唤醒词
```

要点与边界情况：

1. **回答期间计时冻结**：LLM 思考和 TTS 播报都在 worker 线程，mic_loop 播报期间被回声门控 `continue` 短路，超时判断不执行。所以无论机器人回答多慢/多长，都不会出现"答着答着睡着了"。
2. **追问会重置计时**：播报结束后你接着追问，②③再次刷新，30s 重新起算——连续对话期间不会休眠。
3. **超长回答的边界行为**：若单次 TTS 播报超过 30s（罕见），播完后第一个音频块会立刻满足超时条件直接回 IDLE。属合理行为（机器人说完长答案、用户无回应即休眠），如需避免可加大 `--active-timeout`。
4. **休眠时清场**：回 IDLE 前会 `vad.reset()` 清残留段落 + `wake.reset()`，避免休眠瞬间弹出旧音频误触发。

## 5. 实施中发现并解决的坑

1. **KWS 离线回放必须补 ≥1s 尾部静音**：流式 zipformer（chunk-16-left-64，`num_trailing_blanks=1`）需要尾随空帧才输出假设。TTS 生成的音频在末音素截断，不补静音永远不命中——曾因此误判"模型对合成音频失效"。真实麦克风流无此问题；离线测试工具已内置自动补齐。
2. **采样率不匹配**：matcha TTS 输出 22050Hz，KWS 需 16kHz。离线测试工具内置 `np.interp` 线性重采样（round-trip 实验证实重采样不损坏检测精度）。
3. **字符串 keywords 的隐性炸弹**：`keywords="你好小弟"` 会被 `for kw in keywords` 迭代成单字，生成 `n ǐ @你` 这类单字关键词（误唤醒爆炸），且行数校验恰好蒙混过关。已在 `WakeWordDetector.__init__` 加 `isinstance` 显式拦截抛 TypeError。

## 6. 已知限制与调参建议

| 现象 | 调整 |
|------|------|
| 唤不醒（漏唤醒） | `--wake-threshold 0.2`→`0.15` 逐步降低；确认唤醒词连续不停顿地说 |
| 环境音误唤醒 | 阈值提到 `0.3`；换更长的唤醒词（4音节优于3音节） |
| 觉得 30s 休眠太快/太慢 | `--active-timeout 60` / `15` |
| 带口音的"你好"识别差 | 换唤醒词首字避开易混音节；或多词并列 `-w 词A -w 词B` |
