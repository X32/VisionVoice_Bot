## 2. 主程序运行时：线程与数据流

```
python3 src/chat/voice_chat.py
│
├─ 启动序列（主线程）：建 LLM / TTS / Player / ASR → 预合成唤醒应答"哎，我在"
│   └ 预热线程(daemon)：LLM.warmup()（ollama keep_alive=30m，首请求 2.09s→0.25s）
│
├─ 主线程转入 mic_loop（SmartSpeakerASR，唯一麦克风的唯一消费地）
│   │
│   ├ _reader线程(daemon)：stream.read() 阻塞读 → audio_q
│   │      ← ALSA 读停滞被隔离在此线程，2s 后被 mic_loop 放弃重建
│   │
│   └ mic_loop：audio_q.get(timeout=2s)
│       ├ 超时/读错 → daemon关流 → _reset_listeners() → 重建InputStream（~2.5s 自愈）
│       │
│       ├ IDLE 状态：音频 → 唤醒KWS ──命中──→ 切ACTIVE + on_wake()：
│       │       mute → set_playing(True) → Player播预合成应答（垫静音+喂AEC参考）
│       │       → set_playing(False) → unmute(0.8s尾巴)
│       │
│       └ ACTIVE 状态：
│           ├ 播报中(mute窗口)：_barge_check（见 §3）──命中──→ on_barge_in()：
│           │       置 interrupted 标记 → Player.stop()（异步abort，实测3ms静音）
│           ├ 空闲：silero VAD断句 → SenseVoice ASR → on_user_text() → text_q
│           └ 30s 无语音（播报期间计时冻结）→ on_sleep() → 回 IDLE
│
└─ worker线程（单消费者，串行播报；重活全在这里）
    text_q.get() → user入历史 → _chat_with_tools()（见 §4）
      → mute → TTS.speak(play=False) 全量合成
      → 重采样16k → trim静音 + 0.5s先导静音（声卡省电吃首字的对策）
      → set_playing(True)（重建AEC实例 + 停止词KWS换新stream，防状态污染）
      → ChunkedPlayer.play(on_chunk=每块喂far-end参考)（见 §5）
      → set_playing(False) → unmute（打断0.3s / 正常0.8s尾巴）
      → assistant入历史（被打断加"（被用户打断）"标记，模型能答"刚才说到哪"）
```

## 3. 打断判定：`_barge_check` 双通道数据流

```
mic_block(512样本) ──► 不在mute窗口？──是──► 正常路径（VAD断句→ASR）
      │ 否（播报中）
      ├ AEC收敛豁免窗（播报后0.6s）：只喂检测器状态，不触发判定
      │
      ├──► 通道1 停止词：裸 EchoCanceller(aec_kws) ──clean──► 停止词KWS(barge_kws)
      │        ※喂裸AEC：NS管线双讲谱处理毁音素识别           │命中
      │                                              stop_word:不要说了/闭嘴/别说了
      │
      └──► 通道2 长语音：AudioProcessor(HP+AEC+NS) ─clean──► silero(barge_vad)
               ※NS管线能量检测更稳                          │连续语音>1.2s
                                                     long_speech（新问题）
```

- **backchannel 过滤**："嗯/对/好的"（<0.6s、无关键词）两通道都不触发 → 播报继续
- **状态污染防御**：每次 `set_playing(True)` 重建两个 AEC 实例（0.1ms）+ KWS 换新 stream
- **设计不变量**：clean 信号只用于打断判定，绝不进主 VAD/ASR；不打断时门控行为与 R2 前完全一致

## 4. 工具调用回路：`_chat_with_tools`

```
history ──► LLM.chat(tools=TOOL_SCHEMAS, temperature=0.3)
   ├─ 乱码防御：响应无中文/字母/数字 → 降温0.2重试一次
   ├─ 无 tool_calls → 返回最终文本（播报）
   └─ 有 tool_calls → 决议写回历史（可回放格式）→ _exec_tool 本地执行
        get_local_time() 真实 ｜ turn_on_air_conditioner() 占位字符串（R5接真实设备）
        → 结果以 role=tool 回传 → 再问模型（≤MAX_TOOL_ROUNDS，超限强制文本收尾）
```

## 5. 播放链路：ChunkedPlayer 三态有界返回

```
worker: player.play(samples16, on_chunk=asr.feed_reference)
  ├ writer线程(daemon)：按512块写OutputStream，每块后回调喂AEC far-end参考
  │      PortAudioError（abort打断写阻塞）→ complete=False
  └ play() 本体只等三态之一（有界返回保证 → unmute必达，系统不会假死）：
      ① done_evt 置位          → 完整播完 True
      ② stop_evt（+150ms宽限）  → 被打断 False
      ③ 超时（音频时长+2s）      → 打"⚠️播放写线程停滞"告警 → False（ALSA卡死逃生门）

stop()（mic_loop线程经on_barge_in调用）：只置事件立即返回；abort()扔daemon线程执行
      ※绝不同步abort——双工ALSA下会间歇性永久阻塞（真机三次冻结的教训）
```

```
        ┌────────── 唤醒KWS命中（默认"你好小迪"）──────────┐
        │                                               ▼
     ┌──────┐    30s无语音 → on_sleep()    ┌──────────────────────┐
     │ IDLE │◄─────────────────────────── │        ACTIVE        │
     └──────┘                             │ · VAD断句→ASR→LLM→TTS │
       只跑唤醒KWS                          │ · 播报中→打断检测      │
       （音频不进ASR/LLM）                   └──────────────────────┘

```
