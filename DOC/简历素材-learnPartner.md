# learnPartner 简历素材

> 数据口径：全部来自 README「性能参考（本机实测）」与 DOC/ 各实施报告，面试被追问时以 `DOC/报告-*.md` 为准。

## 一、项目一句话

**智能语音交互机器人（个人项目，全链路本地推理）**
端侧全双工语音助手：唤醒词 → VAD 断句 → ASR → 本地 LLM（function calling）→ TTS 流式播报，
支持语义化打断（barge-in）与摄像头视觉监控服务（HTTP+WebSocket）。

**技术栈**：Python · sherpa-onnx（KWS/VAD/ASR/TTS）· WebRTC AEC3 · PortAudio ·
多线程并发（队列/Event/锁）· Ollama / llama.cpp / OpenAI（qwen2.5）· Qwen2.5-VL · OpenCV ·
aiohttp（REST + WebSocket）· function calling

## 二、详细版（简历空间充裕时，选 5~6 条）

- **全链路语音对话管线**：独立完成 唤醒（KWS）→ VAD 断句 → ASR → LLM → TTS 播报的全双工语音助手，全链路本地推理、可离线运行；唤醒响应 ~0.2s、ASR ~100ms，多轮上下文 + function calling，LLM 统一适配 Ollama / llama.cpp / OpenAI 三类后端并支持启动预热消除冷加载。

- **智能打断（barge-in）**：基于 WebRTC AEC3，以播报音频作 far-end 参考实时消回声，双通道语义化判定——停止词 KWS 命中即停播（词长+0.15s）、连续新问题语音 >1.2s 自动停播转收听（开口后 ~1.3s）、"嗯/好的"等反馈语不误打断；回声残留 -25~-37dB、误触发 0 次。

- **音频链路健壮性**：针对 ALSA/PortAudio 间歇卡死设计三层防御（读线程 2s 超时自愈重建 / stop 异步 abort / 播放三态有界返回），核心原则是任何线程不得无限期阻塞在音频 C 调用上；mute/unmute 回声门控保证回声不进主识别链。

- **流式响应改造（核心难点）**：设计 LLM 流式（NDJSON/SSE）→ 按句切分 → 逐句 TTS → 边合成边播放的三线程流水线，双有界队列背压 + Event 生命周期协议；首响延迟从数秒降至 **~1.0s**（30 字回答实测，预算 2s）、句间停顿 0ms；打断即连接级取消上游 LLM 生成。用 faulthandler 抓栈定位并修复两处跨线程死锁（满队丢弃哨兵、全链背压互锁）。

- **视觉监控服务化**：摄像头定时抓拍 + Qwen2.5-VL 场景理解（工作/摸鱼/离开状态判定），aiohttp 实现 REST 快照接口 + WebSocket 双向通道（事件推送/远程命令/心跳），配套断线自动重连的线程化客户端；摄像头/VLM 故障容错降级、服务不崩。

- **工程方法**：建立"合成语料 → AEC → KWS 回放"的离线自动化音频回归测试（五场景，无需真人发声），针对 TTS 合成非确定性设计自愈式测试夹具；需求 → 技术方案 → 实测报告全链路文档化。

## 五、面试深挖点（预期问题 → 答题要点）

1. **首响怎么从 5s 降到 1s？** 预算拆解：首 token 0.13s + 首句合成 0.4s + 0.5s 牺牲
   静音（抗声卡省电吃首字）。关键是按句切分提前出声 + 全流水线并行，而不是任何单点加速。
2. **两个死锁怎么定位的？** 30s 无进展超时告警 + faulthandler dump 全线程栈，看到 worker
   停在无超时 put。根因一：`put(None, timeout)` 满队时丢弃哨兵，消费方永远等不到结束——
   改为 producer_done/synth_done/play_done 三个 Event，结束信号不可丢；根因二：下游满队
   逐级上游阻塞成环——所有队列操作加超时 + 打断位检查，任意打断位可解环。
3. **为什么打断必须 AEC，门控不够吗？** 门控只能"播报时不听"（防回声误识别），无法支持
   "播报中听懂用户插话"。AEC 用播报音频当参考信号消回声，clean 流只做打断判定、绝不进
   主 VAD/ASR——两个机制并存，职责不同。
4. **为什么两个 VAD 实例？** 主 VAD 0.25s 是为断句质量（防短噪声误弹），直接用于打断判定
   慢 0.19s；打断通道单独低阈值实例（0.06s）。同一参数服务两个冲突目标时拆实例。
5. **背压怎么做的？** 有界队列（句队列/段队列），生产者超时 put，满队 + 打断位即退出；
   副作用是打断时上游被节流——历史记录语义相应改为"已读前缀 +（被用户打断）"，保证
   "继续说"仍成立。
6. **ALSA 卡死怎么防？** 原则：不无限期阻塞在 PortAudio/ALSA 的 C 调用上。读侧 2s 超时
   重建流；stop 只置事件、abort 在 daemon 线程；play 三态有界返回（写完/stop/超时）。
7. **引擎线程推事件给 aiohttp 客户端怎么做的？** 引擎在独立线程，经
   `loop.call_soon_threadsafe` 投递到各客户端的 asyncio.Queue；客户端线程化封装、
   断线自动重连，优雅停止用跨线程 set_result 的 future 唤醒阻塞 recv（不用 loop.stop）。
8. **没有真人怎么测音频链路？** 离线回放：合成语音 → 数模混合出回声材料 → AEC → KWS
   判定，五场景脚本化回归；TTS 同文本每次合成波形不同（非确定性），夹具按"多次采样 +
   磁盘 int16 回读校验"自愈生成，避免内存态验证与真实链路不一致。
