# 报时脚本同步 vs 异步模式说明

## 🔄 同步模式 (默认)
```bash
./src/tts/announce_time.sh
# 或
./src/tts/announce_time.sh --sync
```

**行为：**
- 每分钟触发报时后，脚本会**等待音频播放完成**才继续下一轮循环
- 生成音频 → 播放音频 → 等待播放结束 → 继续监控时间

**时间线：**
```
09:00:00 - 开始报时
09:00:00 - 生成音频 (0.2s)
09:00:00 - 播放音频 (3.5s)
09:00:04 - 音频播放完成 ✅
09:00:04 - 继续监控时间...
09:01:00 - 下一分钟报时
```

**特点：**
- ✅ 音频不会重叠播放
- ✅ 听感清晰，每次都能完整听完
- ⚠️ 播放期间脚本"被占用"（但仍在后台计时）
- ⚠️ 如果音频很长（>5s），可能影响下一分钟的精确性

**适用场景：**
- 📢 正式报时、提醒服务
- 🎵 需要完整播报的场景
- ⏰ 重要时间提醒

---

## ⚡ 异步模式
```bash
./src/tts/announce_time.sh --async
# 或
./src/tts/announce_time.sh -a
```

**行为：**
- 每分钟触发报时后，脚本**立即返回**，音频在后台播放
- 启动音频播放 → 立即继续监控时间（不等播放完成）

**时间线：**
```
09:00:00 - 开始报时
09:00:00 - 启动音频播放（后台） ⚡
09:00:00 - 立即继续监控时间...
09:00:03 - (音频仍在后台播放中)
09:01:00 - 下一分钟报时（可能与上一条音频重叠 🔊🔊）
```

**特点：**
- ⚡ 脚本响应快，立即返回监控
- ⚠️ 音频可能重叠（如果上一条还未播放完）
- ⚠️ 多条音频同时播放时，听感混乱

**适用场景：**
- 🔔 频繁简短提醒（<2秒）
- 🎯 后台监控服务（音频只是辅助提醒）
- ⏱️ 对时间精确性要求极高的场景

---

## 📊 对比表格

| 特性 | 同步模式 | 异步模式 |
|------|----------|----------|
| **音频播放** | 等待完成后继续 | 后台播放，立即返回 |
| **音频重叠** | ❌ 不会重叠 | ⚠️ 可能重叠 |
| **听感** | ✅ 清晰完整 | ⚠️ 可能混乱 |
| **脚本响应** | 慢（等音频） | 快（立即返回） |
| **时间精确性** | 一般 | 高 |
| **适用时长** | 任意时长 | 短音频（<2s）为佳 |

---

## 💡 推荐选择

### 使用同步模式（推荐默认）
- ✅ 正式报时服务
- ✅ 重要提醒、闹钟
- ✅ 需要清晰播报的场景
- ✅ 音频时长>2秒

### 使用异步模式
- ⚡ 短音频提醒（<2秒）
- ⚡ 后台监控服务
- ⚡ 对时间精确性要求极高
- ⚡ 能接受偶尔音频重叠

## 🧪 实验对比

**同步模式体验：**
```bash
# 启动同步模式
./src/tts/announce_time.sh

# 观察行为：
# - 每分钟播报一次，完整听完
# - 播放期间脚本暂停
# - 下次播报清晰无重叠
```

**异步模式体验：**
```bash
# 启动异步模式
./src/tts/announce_time.sh --async

# 观察行为：
# - 每分钟立即触发
# - 音频在后台播放
# - 如果音频较长，下次播报时可能重叠
```

## 🔧 技术实现区别

**同步模式代码：**
```bash
if [ "$SYNC_MODE" = true ]; then
    # 等待音频播放完成
    python3 "$TTS_SCRIPT" --text "$TIME_TEXT" --quiet
fi
```

**异步模式代码：**
```bash
if [ "$SYNC_MODE" = false ]; then
    # 后台播放，不等待
    python3 "$TTS_SCRIPT" --text "$TIME_TEXT" --quiet &
fi
```

关键区别：**异步模式末尾的 `&` 符号，让进程在后台运行**
